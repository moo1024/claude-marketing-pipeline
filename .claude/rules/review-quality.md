# Review Quality Rules

## Purpose

Moduus Studio 블로그 초안의 품질 기준을 정의한다.
4축 채점으로 합격/수정 여부를 판정하고, 수정 제안까지 출력한다.

---

## 4축 채점 기준

| 축 | 만점 | 평가 기준 |
|---|---|---|
| SEO | 30 | 메인 키워드가 제목에 포함됨, 롱테일 키워드 3개 이상, 태그 5개 이상, 소제목에 핵심어 포함 |
| 팩트정확도 | 30 | **본문의 모든 수치·기관명·날짜를 원자료와 1:1 대조**해 출처가 확인되는가 (아래 §팩트정확도 채점 상세) |
| 브랜드톤 | 20 | 금지 표현 없음, 운영 사례형 문체 유지, 기관 담당자가 신뢰할 수 있는 톤, 과장 없음 |
| 가독성 | 20 | 7섹션 분량 기준 충족, 문단 흐름 자연스러움, 첫 문장 흡입력, 문장 길이 적절 |

---

## 합격 기준

- **80점 이상**: 합격 — 다음 단계(channel-distributor) 전달 가능
- **80점 미만**: 수정 필요 — Fix 제안 + 재작성 지시
- **단, 아래 팩트 하드게이트를 통과하지 못하면 총점과 무관하게 불합격이다.**

---

## 팩트 하드게이트 (총점보다 우선)

> 이 게이트가 없던 시절, 원자료에 없는 "참여 243명"이 헤징 없이 확정 서술됐는데도
> 팩트정확도 27/30으로 통과했다. 태그 유무만 봤기 때문이다. 아래는 값 자체를 본다.

### 원자료 등급 (정량 수치의 기준은 사용자 원본이다)

이 팀의 실제 흐름은 `사용자 제공 원본(결과보고서·PDF) → archive_draft → 블로그`다.
블로그는 archive_draft의 **파생본**이다. 따라서 블로그를 archive_draft·Notion 아카이브와만
대조하면 **파생본을 원본으로 착각하는 순환 검증**이 된다 — 아카이브에 틀린 수치가 있으면
블로그도 틀린 채 통과한다.

| 등급 | 대상 | 인정 범위 |
|---|---|---|
| **PRIMARY (1순위)** | `.claude/artifacts/fact_sources/[slug]*.md` (사용자 제공 원본 발췌) | **정량 성과 수치의 유일한 근거** — 참여인원·비율(%)·건수·팀수·금액·점수·수상 인원 |
| DERIVED (참고) | `.claude/artifacts/archive_drafts/[slug]-archive-draft.md`, Notion 아카이브 페이지 | 구조·정성 서술(존 개수·프로그램 수·역할 구분)과 날짜의 근거로만 인정 |

- **정량 수치인데 PRIMARY에 근거가 없으면 `[대조 불가]`로 막는다.** archive_draft에만
  적혀 있다는 이유로 통과시키지 않는다.
- PRIMARY 확보는 원칙적으로 **아카이브 단계에서 이미 끝나 있어야 한다**
  (`notion-archive-manager`의 `원자료 포획` 표준 단계 — `archive-structure.md` §4).
  검수 시점에 없으면 검수자가 원본을 확보해 fact_sources에 발췌 저장한 뒤 재실행한다.

---

**게이트 조건 — 하나라도 해당하면 즉시 `[하드게이트 실패]`, 총점 계산과 무관하게 불합격 처리한다.**

1. **미출처 수치 1건 이상** — 본문에 확정 서술된 수치·날짜 중 원자료로 확인되지 않고
   `[확인 필요]`/`[자료 없음]`/`[추정]` 표기도 없는 항목이 하나라도 있으면 실패.
   숫자는 원자료에 있으나 **단위·맥락이 다른 경우(예: 원자료 `18명` ↔ 본문 `18개`)도
   확인으로 인정하지 않으며 실패로 처리**한다.
2. **원자료 부재** — 사용자 원본도 archive_draft도 Notion 원자료도 확보하지 못한 상태에서는
   팩트정확도를 채점하지 않는다. "초안에 적혀 있으니 근거가 있다"는 순환논리를 금지한다.
   → 판정: `[대조 불가 — 원자료 확보 필요]`, 합격 처리 금지.
3. **원자료와 값이 어긋남** — 초안 수치와 원자료 수치가 불일치하면 실패 (예: 원자료 18명 ↔ 초안 141명).
4. **정량 수치의 근거가 파생본에만 있음** — 참여인원·%·건수·팀수 등이 archive_draft에만
   있고 사용자 원본(fact_sources)에 없으면 통과시키지 않는다.
   → 판정: `[대조 불가 — 사용자 원본 확보 필요]`, 합격 처리 금지.

**기계 검증 (필수 실행):**

```bash
python3 scripts/fact_audit.py .claude/artifacts/blog_drafts/[slug]-blog-draft.md
```

- 종료 코드 `0` → 게이트 통과 / `1` → 하드게이트 실패 / `2` → 대조 불가
  - `2`는 두 경우다: `NO_SOURCE`(원자료 파일 없음) / `NO_PRIMARY`(정량 수치 근거가 파생본에만 있음)
- 원자료는 **초안 경로에서 프로젝트 루트를 찾아** 자동 탐색한다. 실행 위치(cwd)와 무관하게
  같은 원자료를 찾으므로, 어느 디렉토리에서 실행해도 결과가 같다.
- `fact_sources/`는 PRIMARY, `archive_drafts/`는 DERIVED로 자동 구분된다.
  사람이 `--source`로 직접 지목한 경로는 PRIMARY로, `--derived-source`는 DERIVED로 본다.
- 이 스크립트는 수치·날짜만 기계 대조한다. **기관명·직함·인용문은 검수자가 직접 대조**한다.
- 일(日) 단위 기간 표현은 날짜 표기와 구분이 어려워 자동 검사 대상에서 빠진다 — 사람이 확인한다.
- 스크립트 통과가 팩트 정확성을 보증하지 않는다. **미검출 = 무죄가 아니다.**

**게이트 실패 시 처리:**
```
## 검수 결과: 수정 필요 — [하드게이트 실패: 미출처 수치 N건]

총점: XX/100 (참고용 — 하드게이트 실패로 합격 불가)
```
Fix 제안에 미출처 항목을 전부 나열하고, 각 항목마다 **① 원자료로 값 확인 ② 헤징 표기 ③ 문장 삭제**
중 하나를 지정한다. channel-distributor 전달·Notion 업데이트는 모두 차단한다.

## 팩트정확도 채점 상세 (30점)

| 항목 | 배점 | 기준 |
|---|---:|---|
| 수치·날짜 출처 대조 | 15 | 모든 수치가 원자료 확인(SOURCED) 또는 헤징(HEDGED)이면 만점. 미확인 항목이 있으면 하드게이트에서 이미 불합격이므로 이 점수는 참고용이다 |
| 기관명·직함·고유명사 | 8 | 주최·주관·협력기관 명칭과 역할 구분이 원자료와 일치. 오류 건당 -4 |
| 인과·단정 표현 | 7 | 확인되지 않은 인과관계("~덕분에 달성했습니다")나 참여자 반응 단정 없음. 건당 -3 |

**채점 시 반드시 지킬 것:**
- 헤징(HEDGED)은 "단정하지 않았다"는 뜻이지 "사실로 확인됐다"는 뜻이 아니다. 감점은 면하되 확인 항목으로 남긴다.
- 헤징은 **문장 단위**로 인정한다. 한 줄 끝의 `[확인 필요]` 하나가 같은 줄 앞 문장의 수치까지 면죄하지 않는다.
- 초안 자체의 "확인 필요사항" 표에 `✅ 확인` 이라고 적혀 있어도, **원자료 대조 없이는 확인으로 인정하지 않는다.**
  초안이 스스로를 근거로 삼는 것이 바로 순환논리다.
- 초안에서 계산된 파생 수치(비율·합계)가 산술적으로 맞아떨어지는 것은 **출처 확인이 아니다.**
  `126/243 = 51.85%`가 맞다는 사실은 243이라는 값의 근거가 되지 못한다.

## 감점 기준 (주요 케이스)

**SEO 감점:**
- 제목에 메인 키워드 없음: -10점
- 롱테일 키워드 2개 이하: -5점
- 태그 3개 이하: -5점

**팩트정확도 감점:** (→ 상세는 위 `팩트정확도 채점 상세` 참조)
- 기관명·직함·고유명사 오류: 건당 -4점
- 확인 안 된 인과관계·참여자 반응 단정: 건당 -3점
- ※ **미출처 수치는 감점이 아니라 하드게이트 실패다.** 점수로 희석하지 않는다.

**브랜드톤 감점:**
- 금지 표현 1개당 -5점 (blog-tone.md 기준)
- 행사 후기식 나열 구조: -10점
- 기관 홍보문 투의 문장: -5점

**가독성 감점:**
- 섹션 분량 미달(2개 이상): -5점
- 문단 전환 부자연스러움: -5점
- 첫 문장이 숫자/장면/문제의식으로 시작하지 않음: -5점

## Fix 루프 규칙

1. 80점 미만이거나 **하드게이트 실패**면 Fix 제안을 출력하고 수정을 요청한다.
2. 수정 후 재채점을 진행한다. **재채점 시 `fact_audit.py`를 반드시 다시 실행한다.**
3. 최대 3회까지 반복한다.
4. 3회 후에도 80점 미만이거나 하드게이트를 통과하지 못하면 `[수동 개입 필요]`로 표시하고 중단한다.
5. **하드게이트 실패는 Fix 횟수와 무관하게 합격으로 전환되지 않는다.** 미출처 수치를 실제로
   원자료로 확인하거나, 헤징 표기하거나, 삭제해야만 통과한다.

## 리뷰 리포트 출력 형식

```
## 검수 결과: [합격 / 수정 필요 / 수정 필요 — 하드게이트 실패]

총점: XX/100

## 팩트 하드게이트: [통과 / 실패 — 미출처 N건 / 대조 불가 — 원자료 없음 / 대조 불가 — 정량 수치 근거가 파생본에만 N건]

대조한 원자료:
- PRIMARY(원본): `.claude/artifacts/fact_sources/[slug]-source.md` — 「[결과보고서명]」 발췌
- DERIVED(파생): `.claude/artifacts/archive_drafts/[slug]-archive-draft.md`
- DERIVED(파생): Notion: [페이지명] (읽기 전용)

### 수치 대조표 (본문의 모든 수치·날짜를 빠짐없이 기재)

| 본문 수치 | 위치 | 원자료 근거 값 | 출처 | 판정 |
|---|---|---|---|---|
| 243명 | S5 | 원자료에 없음 (목표 100명 / 실제 [확인 필요]) | — | ❌ 미출처 |
| 100명 | S5 | 목표 참여자 100명 | fact_sources(원본) 개요 | ✅ 확인 |
| 18명 | S3 | 사전 신청자 18명 (구글폼) | fact_sources(원본) 2.1 | ✅ 확인 |
| 31팀 | S4 | 원본에 없음 / archive_draft에만 기재 | archive_draft(파생) | ⛔ 파생본만 |
| 6개 존 | S3 | 6개 프로그램 존 운영 | archive_draft(파생) | ✅ 확인(구조) |

판정 표기: `✅ 확인` / `✅ 확인(구조)` / `⚠️ 헤징` / `❌ 미출처` / `❌ 값 불일치` / `⛔ 파생본만`

`출처` 열에는 등급을 함께 적는다 — `fact_sources(원본)` / `archive_draft(파생)`.
**정량 수치(참여인원·%·건수·팀수·금액)에 `archive_draft(파생)`만 적히면 `⛔ 파생본만`이며,
그 건이 1건이라도 있으면 `[대조 불가]`로 중단한다.** 구조 서술은 파생본 근거로 `✅ 확인(구조)`.
```

## review_diff 출력 형식

Fix 루프 완료(합격 또는 3회 종료) 시 content-editor-reviewer가 아래 형식으로
`.claude/artifacts/blog_reviews/[slug]-review-diff.md`를 생성한다.

```markdown
# Review Diff — [slug]

- 초안 기준: `.claude/artifacts/blog_drafts/[slug]-blog-draft.md`
- 검수 리포트: `.claude/artifacts/blog_reviews/[slug]-review.md`
- 생성 일자: YYYY-MM-DD
- 최종 총점: XX/100
- 판정: PASS

## 1. 검수 이력

| 회차 | 총점 | 문제 축 | 주요 수정 요청 | 결과 |
|---:|---:|---|---|---|
| 1차 | XX/100 | SEO, 가독성 | 제목 키워드 추가, 첫 문장 교체 | Fix 요청 |
| 2차 | XX/100 | — | — | 합격 |

## 2. 축별 변경 요약

| 축 | 기존 문제 | 수정 방향 | 반영 결과 |
|---|---|---|---|
| SEO | | | |
| 팩트정확도 | | | |
| 브랜드톤 | | | |
| 가독성 | | | |

## 3. 최종 반영 요약

- 제목/도입:
- 본문 구조:
- 팩트/수치:
- CTA:
- 금지어/톤:

## 4. 남은 확인 필요 사항

- [확인 필요] 항목이 없으면 "없음"으로 표시한다.
```

**판정 기준:**
- 80점 이상 **그리고 하드게이트 통과** → `판정: PASS`
- 하드게이트 실패로 종료 → `판정: FACT_GATE_FAILED` (총점이 80점 이상이어도 PASS 금지)
- 원자료 미확보로 대조 불가 → `판정: NO_SOURCE`
- 정량 수치 근거가 파생본에만 있어 대조 불가 → `판정: NO_PRIMARY_SOURCE`
- 3회 후 미합격 종료 → `판정: NEEDS_MANUAL_REVIEW`

review_diff의 `## 4. 남은 확인 필요 사항`에는 **헤징(⚠️) 처리된 수치를 전부 나열**한다.
헤징은 통과 사유이지 확인 완료가 아니므로, 발행 전 사람이 확인할 목록으로 남긴다.
