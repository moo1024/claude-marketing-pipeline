# Archive Structure Rules

## Purpose

이 규칙은 Notion 행사 아카이브 페이지를 채울 때의 표준 구조를 정의한다.

행사/용역이 완료된 후, 해당 Notion 페이지에 어떤 속성과 본문 섹션을 어떤 순서로 채울지 고정한다.  
이 구조를 따르면 이후 블로그 초안 생성, 포트폴리오 사례화, 제안서 문장 추출이 일관되게 가능해진다.

---

## 1. 속성 채우기 기준

행사 페이지의 DB 속성은 아래 순서로 우선 채운다.

| 우선순위 | 속성명 | 채우는 기준 |
|---------|--------|------------|
| 1 | 행사명 | 공식 명칭 그대로 |
| 2 | 행사 날짜 | 시작일 ~ 종료일 (결과보고서 기준) |
| 3 | 상태 | 완료 / 진행 중 / 시작 전 |
| 4 | 내 역할 | 실제 수행한 역할 (예: 운영사무국 총괄) |
| 5 | 협력기관 | 발주처·주관기관 명칭 |
| 6 | 대상 | 참여자 대상 (예: 대학생, 일반인, 청소년) |
| 7 | 유형 | 행사 / 특강 / 해커톤 / 교육과정 / 공모전 / 컨설팅 / 서포터즈 / 클래스 |
| 8 | 연도 | 2025 / 2026 |
| 9 | 핵심 키워드 | SEO 및 검색용 키워드 (쉼표 구분) |
| 10 | 사용 도구·기술 | 사용한 툴·기술 태그 |
| 11 | 참여 인원 | 총 참여자 수 (확인된 숫자만) |
| 12 | 블로그 상태 | 미작성 / 초안 / 발행완료 |

> ⚠️ 의미가 불확실한 속성(예: `포트폴리오 포함`)은 임의로 수정하지 않는다.

## 4. 원자료 포획 (fact_sources) — 표준 단계

아카이브 초안을 만들 때 **입력 원본의 수치 구간을 함께 발췌 저장한다.**
저장 위치: `.claude/artifacts/fact_sources/[slug]-source.md`

**왜 아카이브 단계에서 하는가**
파이프라인은 `사용자 제공 원본(결과보고서·PDF) → archive_draft → 블로그`로 흐른다.
블로그도 아카이브도 원본의 **파생본**이다. 나중에 블로그를 archive_draft와만 대조하면
파생본끼리 대조하는 순환 검증이 되어, 아카이브가 잘못 옮겨 적은 값이 그대로 발행된다.
원본은 **사용자가 자료를 건네는 이 시점에만** 손에 있으므로 여기서 잡아둔다.

**발췌 대상** — 원문에 인쇄된 값 그대로
- 수치: 참여 인원, 신청자 수, 팀 수, 제출 건수, 비율(%), 금액, 점수, 수상 인원
- 날짜·시간: 행사일시, 모집기간, 후속 일정
- 기관명·과업명·직함, 인용문

**작성 규칙**
- 값마다 출처를 명시한다 (예: `결과보고서 p.12 표 3`, `「2.1 참여 학생 수」`).
- 원본이 같은 지표를 다른 값으로 표기하면 **인쇄된 값을 모두 남기고** 채택값과 근거를 적는다.
- 원본에 없는 값은 적지 않는다 (검증 우회 금지). 없으면 `[자료 없음]`, 불확실하면 `[확인 필요]`.
- 형식 상세: `.claude/artifacts/fact_sources/README.md`

원본이 구두 전달뿐이라 발췌할 텍스트가 없으면 파일을 억지로 만들지 않고,
`확인 필요사항`에 `[원자료 미확보 — fact_sources 없음]`으로 남긴다.
이 경우 이후 검수에서 정량 수치는 `[대조 불가]`로 막힌다 (`review-quality.md` 팩트 하드게이트).

## 5. 완성 기준 체크리스트

아래 항목을 모두 채워야 아카이브 완성으로 본다.

- [ ] **원자료 발췌 저장** — `.claude/artifacts/fact_sources/[slug]-source.md` (없으면 사유 명시)
- [ ] 속성 12개 중 확인 가능한 항목 모두 입력
- [ ] 행사 개요 표 완성
- [ ] 내 역할 1문단 작성
- [ ] 주요 활동 단계별 정리 (최소 3단계)
- [ ] 성과 수치 기록 (없으면 `[자료 없음]` 표기)
- [ ] 블로그 각도 최소 3개
- [ ] 도입부 버전 최소 1개
- [ ] SEO 키워드 최소 5개
- [ ] 제안서/포트폴리오 재사용 포인트 최소 1개
- [ ] 확인 필요사항 정리
- [ ] Notion 반영 전 승인 필요사항 명시
- [ ] 블로그 상태 → `초안` 이상으로 업데이트 (Notion 반영 시)
